# Equinox BakaSU Edition 2.0.1

Equinox Kernel by **[LF52406](https://github.com/LF52406)** for the POCO F5 Pro / Redmi K60 (`mondrian`),
BakaSU edition by **Nanairo8890** with LF52406's permission

Same kernel as 2.0 (BakaSU 548d1dda, SUSFS v2.4.0, NoMount v2.2.0). 2.0.1 only adds hiding KernelSU's own
SELinux types from apps

## Files

- `Equinox-5.10.269-BakaSU-2.0.1-mondrian.zip`: AnyKernel3 zip. Flash it from a recovery or a kernel
  flasher; it checks the ROM's vendor modules and then replaces only the kernel `Image`, keeping the
  ROM's ramdisk, header and bootconfig
- `Equinox-5.10.269-BakaSU-2.0.1-mondrian-checkonly.zip`: the same package, named so that it only runs
  the check and flashes nothing. Use it to find out whether your ROM is compatible
- `BakaSU_v4.2.0-rc3_35257-arm64-v8a-release.apk`: the official BakaSU manager, from BakaSU's CI
- `CHANGELOG.en.txt`, `CHANGELOG.es.txt`, `CHANGELOG.pt-BR.txt`, `CHANGELOG.ru.txt`: full changelog

## Before flashing

- Back up your `boot` partition first
- If you update your ROM, flash the zip again afterwards, because the ROM ships its own kernel
- 2.0.1 keeps the same BakaSU 35257 manager and the NoMount metamodule as 2.0

## What 2.0.1 adds

- **Hiding KernelSU's own SELinux types from apps.** KernelSU creates its own types in the SELinux policy
  (`ksu` and `ksu_file`); an app could confirm they existed by querying them through the SELinux
  filesystem, which gave root away. When it applies its rules the kernel now registers those two types in
  SUSFS's hidden-types list, which is only consulted for apps (uid 10000 or higher), so to an app they
  answer as non-existent (EINVAL), like a context that is not in the policy. The kernel's own context
  resolution and the granting of root do not change. This is the same approach Magisk and LSPosed use
- **No KMI change.** The change is in KernelSU's code and touches no exported symbols: 0 changed CRCs and
  0 removed symbols against clean Equinox (only `put_pid_ns` is added, same as 2.0), so the compatible
  ROMs are the same as 2.0
- **What it does not fix.** It does not turn Duck Detector or similar detectors green: signals that do not
  come from the kernel remain, such as the TEE (TEESimulator), the Vector/LSPosed types and the ROM's own
  contexts. From the kernel only what the kernel adds can be hidden
- The change is applied as a patch over the KernelSU submodule at build time
  (`scripts/equinox/patches/0001-susfs-hide-ksu-types.patch`), so the submodule stays pinned and BakaSU
  is not forked

## Compatible ROMs

2.0.1 exports the same symbol CRCs as 2.0, so the same ROMs are compatible:

- **Compatible:** MistOS 5.1 Beta (20261011 to 20261025) and MistOS 5.0 Alpha 20260914; the latest builds
  from Keosh with the kernel `5.10.269-gki-g1598dc02ea84`: crDroid 12.12 (20260928), Evolution X 11.11,
  Infinity-X 3.12 (VANILLA, GAPPS core and extra), Lunaris 3.12 (VANILLA and GMS), LineageOS 23.2
  (20260929) and Axion 2.8 (VANILLA and GMS); Infinity-X 4.1 by LF5 (17.10.2026); crDroid 12.12 by Taha
  Keles (20260930)
- **Not compatible:** AOSPA calcite and PenguinOS celerity. They use their own kernel
  (`5.10.269-beryl-7156c6f9fb`) and the installer stops on them

## Checks

- KMI against clean Equinox: 0 changed CRCs and 0 removed symbols (only `put_pid_ns` is added). The
  `vmlinux.symvers` is identical to 2.0
- Vendor module CRCs: 337 from `vendor_boot` and 390 from `vendor_dlkm` match MistOS 5.1 Beta 20261025,
  Infinity-X 4.1 and the stock modules
- This is the same SELinux change as in the FinaSU edition, which was tested on the phone (apps see `ksu`
  and `ksu_file` as non-existent, with `susfs: hide ksu type ... ret=0` in `dmesg`). This BakaSU edition
  has not yet been tested on the phone or flashed for this version
